✦ CREATE2 vanity address grinder

Grind a vanity smart-contract address by searching CREATE2 salts. No private keys are involved anywhere: the address is a pure function of your deployer, your init code and the salt, so the result is one keccak away from being re-derived by anyone. Runs entirely in your browser.

This grinds a vanity contract address. Because there is no key, a hostile grinder's worst case is handing you a salt that does not work, which one keccak disproves. Want a vanity wallet you hold the key to? That is a different tool with a very different risk model: evm-vanity.

40 hex characters, decided by a deployer, an init code and one number you choose.

1. Factory and init code

CREATE2 fixes the deployer address and the init code; only the salt is yours to choose.

address = keccak256(0xff ‖ deployer ‖ salt ‖ keccak256(initCode))[12:]

Have the raw initCode instead (deploy bytecode with the ABI-encoded constructor arguments appended)? Paste it and it is hashed here. Have a Foundry or Hardhat artifact? Drop the JSON in and the bytecode is read out of it.

2. Pattern

Hex characters only (0-9, a-f). Each extra character is 16x harder. Mixed case (e.g. Beef) matches the EIP-55 checksum: distinctive, and 2x harder per letter.

The same address, on every chain

Same deployer, same init code, same salt gives the same address on every chain where that deployer exists. All four common deterministic factories are live on Ethereum, Base, Arbitrum, Robinhood Chain, OP, Polygon, BNB and Avalanche, each row confirmed by eth_getCode.

The deploy page checks the predicted address is still unclaimed on all of them before you send anything, which is the failure mode nobody warns you about: somebody else's deployment can already occupy your address on one chain while it is free on the rest.
