Quick start

Grind in the browser at the grinder. Nothing is installed and nothing is transmitted.

git clone https://github.com/nirholas/create2-vanity
cd create2-vanity
npm install
npm run dev          # site on :5182, API on :8789

Or from the command line:

npx create2-vanity hash --artifact out/Token.sol/Token.json
npx create2-vanity grind --init-code-hash 0x30f9… --prefix beef
npx create2-vanity available 0x00000000D49195AE81759cd247cFeDD9D0B479df

The derivation

EIP-1014 defines a contract address deployed with CREATE2 as

address = keccak256(0xff ‖ deployer ‖ salt ‖ keccak256(initCode))[12:]

Four public inputs, one hash, twenty bytes out. No private key appears anywhere in that expression, and that single fact changes everything about this tool compared with a wallet grinder:

  • a hostile grinder's worst case is handing you a salt that does not work, which one keccak disproves;
  • the work can be delegated to anyone, on any machine, with nothing to protect;
  • server-side grinding is enabled by default here, because refusing to do it would be theatre;
  • an attestation about the address is checkable rather than merely signed.

The sibling question, "which address will my next ordinary deploy land on", is keccak256(rlp([sender, nonce]))[12:], and create2-vanity derive --sender … --nonce … answers it.

Init code, and the mistake everyone makes

Init code is the deploy bytecode with the ABI-encoded constructor arguments appended. Hashing the bytecode alone is the single most common reason a predicted address turns out to be wrong, and it is discovered after the grind, after the deployment, and after the money.

Load a Foundry or Hardhat artifact on the grinder page and it reads the bytecode out of it, then reads the ABI and tells you, in red, how many constructor arguments the contract declares and of what types. The same check runs in the CLI: 

$ create2-vanity hash --artifact out/Token.sol/Token.json
✦ 0x9c2f…
  Token, 4210 bytes of deploy code

  This contract takes 2 constructor arguments:
    address owner
    uint256 cap
  The hash above covers the deploy code alone. Append the ABI-encoded arguments
  before grinding, or the address you find is not the address you deploy to.

Encode the arguments with whatever produced the artifact (cast abi-encode, ethers, viem) and concatenate.

Difficulty

An address is 40 uniform hex nibbles, so an n-character pattern costs 16n expected salts, at either end. 0x0000… costs exactly what 0xdead… costs, and a suffix costs what a prefix costs.

EIP-55 casing is the exception. A specific case spelling costs an extra factor of two per letter, so Beef is sixteen times harder than any-case beef. Every quote reports the multiplier.

Grinding is geometric, so the expected value is not a deadline: at the expected count you have had a 63.2% chance of finishing. Quotes report p50, p90 and p99.

One keccak over 85 bytes is cheap, so this grinder is fast: hundreds of thousands of salts per second per core, an order of magnitude beyond a wallet grinder, which pays for an elliptic-curve operation per candidate.

Portability is not availability

The same deployer, init code and salt give the same address on every chain where that deployer exists. That is the reason to use CREATE2 at all, and it comes with a failure mode nobody warns about: the address can already be occupied on one chain while it is free on the rest.

Somebody else's deployment, an earlier deployment of your own, or a squatter can hold it. Deploying into an occupied address fails and costs the fee. The deploy page checks every chain first, then re-checks the chain you picked immediately before sending, because a table can be minutes old by the time anyone clicks. 

$ create2-vanity available 0x00000000D49195AE81759cd247cFeDD9D0B479df
  Ethereum                   free
  Base                       occupied
  Arbitrum One               occupied
  Robinhood Chain            free
  …

All four common deterministic deployers (the Arachnid proxy, CreateX, Safe v1.4.1 and the Coinbase Smart Wallet factory) are live on Ethereum, Base, Arbitrum, Robinhood Chain, OP, Polygon, BNB and Avalanche. Each row was confirmed with eth_getCode, and npm test re-confirms it.

Attestations

An attestation records who ground a salt, when, and how many attempts it took, signed as EIP-712 typed data so a contract can recover the signer with ecrecover.

It is an unusually honest document, because its central claim is not a claim: the verifier re-derives the address from the attested deployer, salt and init-code hash. A lie fails in one keccak, with or without the signature. The signature adds provenance, never authority, which is why losing the issuer key would cost this service its identity and cost users nothing. 

import { verifyAttestation } from 'create2-vanity/attestation';

const issuers = (await (await fetch(BASE + '/.well-known/create2-vanity.json')).json()).issuers.map(i => i.address);
const result  = verifyAttestation(attestation, { issuers });

result.checks.find(c => c.id === 'derivation').pass;   // needs no issuer at all

The type hash and domain separator are served at /.well-known/create2-vanity.json so a deployed Solidity verifier and this library cannot drift apart. The domain carries no chainId, because the address is the same everywhere.

HTTP API

Machine-readable schema: /openapi.json. Agent card: /.well-known/agents.json.

EndpointWhat it does
POST /api/deriveCREATE2 from a deployer, salt and init code; CREATE from a sender and nonce.
POST /api/quoteExpected salts, p50/p90/p99, rarity and the EIP-55 case multiplier.
POST /api/grindSearch salts server-side. Enabled by default: there is nothing to leak.
POST /api/availabilityIs the address still free, chain by chain.
POST /api/attestSign an EIP-712 grind attestation.
POST /api/verifyVerify one, derivation check included.
GET /api/chainsThe chain and deployer registry.
GET /api/saltA random 32-byte salt.

       "salt":"0xfc1ecd1953bb17cf798c1eaeed287873008f3a3038f438e9e74c3b33ce370ef5",
       "initCodeHash":"0x30f9d9020bf9622bbe7f8a1625d447efe350dfafd0a91e6dbd62d56547db835f"}'

CLI

npx create2-vanity hash --artifact out/Token.sol/Token.json
npx create2-vanity grind --init-code-hash 0x30f9… --prefix beef --out found.json
npx create2-vanity derive --deployer 0x4e59… --salt 0xfc1e… --init-code-hash 0x30f9…
npx create2-vanity derive --sender 0x6ac7… --nonce 3
npx create2-vanity quote --prefix Beef --rate 700000
npx create2-vanity available 0xBEEF… --deployer 0x4e59…
npx create2-vanity verify attestation.json
npx create2-vanity chains

Add --json to anything for machine-readable output. available exits non-zero when the address is occupied somewhere, so it drops into CI.

  }
}
create2_deriveCREATE2 or CREATE address derivation.
create2_quoteDifficulty and rarity for a pattern.
create2_grindGrind a salt across every core.
create2_availabilityIs the address free, chain by chain.
create2_verify_attestationVerify an attestation offline.
create2_chainsChains and their deployers.

No key material passes through any of them, which is what makes this safe to let an assistant drive unsupervised.

Self-hosting

npm run build
ATTESTATION_KEY=$(node server/keygen.mjs | head -1 | cut -d= -f2) npm start
npm run build
npx wrangler secret put ATTESTATION_KEY
npx wrangler deploy
VariableMeaning
ATTESTATION_KEY32-byte secp256k1 key (hex) for signing attestations. Unset means an ephemeral per-process key, reported in every response. It is a signing identity, not a wallet: do not fund it.
PORTNode listen port. Default 8789.

Every endpoint behaves identically on Node and on Cloudflare Workers: the grinder is pure keccak with no filesystem or WebAssembly dependency.
